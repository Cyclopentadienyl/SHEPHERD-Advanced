更正：手動指定版本的能力已存在
scripts/build_pyg_arm.sh 已支援 PYGLIB_SPEC、SCATTER_SPEC、SPARSE_SPEC、CLUSTER_SPEC。
例如指定值 PYGLIB_SPEC=git+https://github.com/pyg-team/pyg-lib.git@0.8.0 可選建置來源（亦可指定完整 commit）。deploy.sh 呼叫 builder 時繼承這些環境變數。
未指定 PYGLIB_SPEC 時，腳本從目前 Torch／CUDA 對應的 data.pyg.org 索引選最高版本；這次索引解析到 0.8.0，並不是無條件抓 Git HEAD。其他三套件預設 spec 未固定版本。
因此應記錄的改善是「部署選項不顯眼，下載失敗轉自編譯可能改變套件版本」，不能誤報成完全沒有版本指定能力。
另需區分建置與安裝：builder 最後以未附版本的套件名配合 --find-links 安裝，不能只憑有 SPEC 選項便保證任何環境下都裝入要求的版本。精確安裝本次產生的 wheel 並核對實裝結果，是更可靠的方式；本次的四個 wheel 與實裝原生程式庫已逐一比對相同。

- 資料指紋／模型檔案 digest 與執行環境是不同資訊；不能因為換了 PyG，就假裝原模型或資料內容也換了。
- sidecar.py 的 environment 欄位保留原始事實，但不納入既有條件摘要；不能只看同一 group digest 就認定 PyG／driver 完全相同。條件分組也不能變成拒絕跨環境比較或登錄的門檻。
