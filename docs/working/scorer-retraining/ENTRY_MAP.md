# Entry map: kept, changed or retired

**Status: the K0 inventory of the code at `0e64666`** (2026-10-27), for the A + B integration
([`README.md`](README.md) §8 and §10). Six read-only mapping passes read the code by area
(training; models; data, graph and sampling; inference and evaluation; API and WebUI; probes,
tests and documents), and one completeness pass checked what they missed. Each row gives the
entry, where it is, its verdict, its role after the switch, its callers and its tests.

- **Verdicts.** *keep*: unchanged. *modify*: kept, changed. *replace*: a new component takes the
  role. *retire*: removed when its callers move; K7 checks that none is left. *uncertain*:
  decided at the node that touches it, against the blueprint.
- **A guide, not a contract.** Line numbers are those of `0e64666` and drift as nodes land. A row
  found wrong is corrected at the node that touches it; the blueprint decides, not this map.
- **Retirement follows callers** (README §7, §8): an entry retires in the commit that moves its
  last caller, and K7 is the final check.

## Hazards the passes found

Each is a place where the blueprint meets code that would silently do something else. The node
that touches the place resolves it; none is accepted by default.

**Training**

- Layering decides where the shared code can live. .import-linter.ini:20-32 puts src.training below src.evaluation and src.inference, and above src.models and src.utils. So Trainer validation cannot import measurement's ranking or metrics. The one metrics/tie implementation required by decisions §2 and 7.6 must sit in src.models or below; the Trainer already uses src/utils/metrics.py at trainer.py:83,852. Likewise, if the task modules that return named loss terms live in src.models (README §3.1), the one loss module must also be in src.models, because src.models cannot import src/training/loss_functions.py.
- Fake optimizer updates. MultiTaskLoss starts from a leaf torch.tensor(0.0, requires_grad=True) (loss_functions.py:509) and adds only the terms whose inputs exist. A batch with no valid term still goes through backward and _optimizer_update (trainer.py:676-691). That counts optimizer_updates and steps the scheduler (trainer.py:756-765), although AdamW changes no parameter whose grad is None. This contradicts the R1 rule: an LP-only base must not make a fake update when a batch has no valid LP term. Under a fp16 GradScaler the same path is likely to raise in scaler.step because no inf checks were recorded (plausible, not reproduced).
- GradientClipping callback (callbacks.py:657-679) is misnamed and wrong. It never clips; the real clip is at trainer.py:738-744. It reads p.grad in on_batch_end, which the Trainer calls after _optimizer_update has run optimizer.zero_grad() (trainer.py:689-699, 768). In torch 2.x that sets grads to None, so the logged grad_norm is 0 on every update batch. It also syncs the host once per parameter.
- ModelCheckpoint's filename template is hard-coded to 'model-{epoch:02d}-{val_mrr:.4f}' (trainer.py:500), while monitor and mode come from config (trainer.py:489-491, 502-503). A base stage that monitors LP accuracy, with no val_mrr key in its logs, raises KeyError in str.format at the first best-k save (callbacks.py:310-313).
- Early stopping cannot be turned off. _create_default_callbacks always installs EarlyStopping with restore_best_weights=True (trainer.py:487-494), and patience must be at least 1 (training_fields.py:350-353; API ge=1). Decision 7.4 says early stopping must be explicitly disabled, not faked with a huge patience, if the upstream full schedule plus best-validation checkpoint is used. The README's C6 row (docs/working/scorer-retraining/README.md:154) instead says to use the existing EarlyStopping with a recipe patience. The two texts disagree and the code supports only the README.
- run_plan._inherit_settings requires the parent's recorded config.requested key set to equal the current TrainConfig field set (run_plan.py:248-252 refuse unknown keys, 271-274 refuse missing ones). Removing use_ortholog_gate or the loss weights, or adding learning_stage/task, makes every existing checkpoint impossible to continue. That fits the single switch for old checkpoints, but every later TrainConfig change will also strand new-contract checkpoints unless the compared set is versioned with the spec.
- Finetune does not fit run_plan. plan_continuation knows only resume and extend (run_plan.py:81, 177-198) and refuses stopped_early parents (177-182). README §4 and §8 regression 8 require an early-stopped or weights-only base that has a model_spec to be accepted as a finetune parent and refused as a resume. Finetune needs its own operation and planner. Routing it through plan_continuation, or loosening resume, would break the M3a contract.
- The checkpoint selection metric is local and truncated. _run_evaluation_pass ranks only the disease columns of each sampled batch subgraph and keeps local indices truncated at 20 (trainer.py:842-848). RANKING_SCORE_KEYS (checkpoint_paths.py:58) then rank checkpoints by that val_mrr for serving auto-selection, the Models validation figure and the pipeline's checkpoint_meta (inference/pipeline.py:146). U6 needs exact all-disease ranks and the base needs LP accuracy. Serving auto-selection has no task filter (checkpoint_paths.py:569-597; api/routes/pipeline.py:446-451), against README §4 ('task filter first').
- The run layout and the hetero factory share one conv-type tuple. list_runs looks only at runs/<t> for t in SUPPORTED_CONV_TYPES (checkpoint_paths.py:316-317), and normalize_conv_type deliberately rejects 'gatv2' (checkpoint_paths.py:82-97). A GATv2 reference run would be invisible to listing, selection, the WebUI (training_console.py:1035-1038) and the API until SUPPORTED_CONV_TYPES (model_types.py:27) changes. That same tuple is the hetero layer factory's supported list (layers.py:50, 166-170), so the encoder ids for spec/layout/UI need separating from the factory's conv list.
- Unknown config keys are dropped silently. load_config_with_explicit copies a YAML key only if TrainConfig has that attribute (train_model.py:470-473). After retirement, a YAML file or API-generated config that still sends use_ortholog_gate, contrastive_weight, label_smoothing and so on would be ignored without a word. K7 and BACKLOG 54 require explicit refusal. Only the probe asserts no unknown keys, and only for its own file (probe_deployment.py:5638-5640).
- Exit code for runs without validation. _train_main returns 0 only if metrics is non-empty (train_model.py:1366). Trainer.train returns {} whenever there is no val loader (trainer.py:614-617), and an empty val split is an explicitly supported case (train_model.py:626, 875-890). So a completed run without validation exits 1, and setup_demo.py:293 and probe_deployment.py:1737-1738 treat it as failure. The new stages must always produce a validation report or change this contract.
- The reader blocks a base-only run. read_training_inputs always reads train and val DiagnosisSample files and refuses an empty training cohort (train_model.py:609-625). A KG-only base pretraining run has no patients. The recorded roles (training_input_digests:820-844) and the resume role check (check_resume_parent:770-781) are fixed to disease roles and have no edge-split, graph-view or reference-cohort role.
- Defaults are copied in six places and differ from the reference: TrainConfig (train_model.py:156-244), TrainerConfig (trainer.py:92-142), LossConfig (loss_functions.py:64-82), the API TrainingStartRequest (api/routes/training.py:90-133), WebUI _collect_config (training_console.py:281-357) and training_fields FIELDS, kept in sync by the test_training_fields.py parity tests. Today: 4 layers, 8 heads, dropout 0.1, wd 0.01, fp16 AMP on, cosine with 500 warmup, seed 42, early stop at 10. Upstream reference: 3 layers, 4 heads, dropout 0.3, wd 0, fp32, constant LR, seed 1. The recipe should have one source (the spec), not six copies kept in step.
- Structural-compatibility writers and readers are still live. Trainer._serialize_config writes model_config plus flat architecture mirrors 'for interim inference builds' (trainer.py:1119-1137). They are read by resolve_arch_params' key-name inference (model_types.py:75-207, via shepherd_gnn.py:576 for serving and measurement), the training_manager continue preview (training_manager.py:1830), probe_deployment.py:5719 and migrate_checkpoints.py:74,80. Under the single switch these readers must move to model_spec in the same change that retires the writer.
- The only switch-boundary check today is CHECKPOINT_RECORD_VERSION=1 (checkpoint_io.py:38), and only run_plan reads it (run_plan.py:153). Listing (_read_one, checkpoint_paths.py:477-508), serving and measurement check neither record_version nor model_spec. README §8 regression 7 requires an explicit refusal at every consumer.
- The Trainer hard-codes the heterogeneous batch format: batch_data['batch'/'subgraph_x_dict'/'subgraph_edge_index_dict'] and self.model(x_dict, edge_index_dict) (trainer.py:658-665, 819-825). The new task module must own batch interpretation and the forward pass (README §3.1). Otherwise base, finetune and each task would fork the Trainer, which the one-Trainer rule forbids.
- Resume does not restore random state. The seed is re-applied in Trainer.__init__ (trainer.py:296-297), and continue_from restores no RNG or sampler state (trainer.py:1254-1259; the payload has none, checkpoint_payload.py:209-221). This is documented (PLAN_PROVENANCE_CONTRACT.md:2646), but the gene upsampling counter and node-epoch sampler state (decision 7.5) need explicit checkpoint state.
- Optimizer parameter groups come from name substrings (trainer.py:313-330). The number of groups drives the extension's fixed-rate list (run_plan.py:322-325; trainer.py:1239-1243), so changing the grouping changes what continuation records. MultiTaskLoss.log_vars are not in the optimizer or the state_dict, because loss_fn is not a submodule of the model. Any learned loss parameter in the new design must be part of the one bundle.
- Dead or parallel paths to remove: Trainer.metrics=DiagnosisMetrics() is never read (trainer.py:265); get_model_info has no callers (trainer.py:1066); evaluate has only test callers (trainer.py:1006); ProgressBar is unused (callbacks.py:617); allocate_run_dir and ranking_score_from_logs have no callers (checkpoint_paths.py:258, 76). TrainerProtocol (src/core/protocols.py:1171-1225) declares train(model, train_data, ...), which does not match Trainer.train(); runtime_checkable checks only names.
- The cross-field rule hidden_dim_divisible_by_num_heads (training_fields.py:101-115) is keyed on conv_type 'gat' and assumes the hetero GATConv's hidden//heads with concat. In the reference GATv2, the concat widths are output × heads (README C1: 128×4=512), so the rule is wrong for it and must become encoder-specific (README C1, 'width comes from the model spec').
- The finetune graph rules must not be mixed with the base's. D5 says target edges plus their reverse and duplicate forms leave message passing in both stages, and base validation uses training edges only. The decisions (7.1) say finetune sees the full view while base LP validation keeps its own train-graph rule. Today's Trainer has no notion of graph exposure, so these rules have to be recorded per stage in the payload (README §4, 'which graph each stage saw'), not inferred.

**Models**

- Gate off means ortholog edges are dropped, not treated as ordinary relations: ShepherdGNN splits ortholog-classified edge types out of the core edges (src/models/gnn/shepherd_gnn.py:216) and uses them only through the gate (:223-228). A CPU probe gave bit-identical outputs with and without those edges when use_ortholog_gate=False. The S1 view must decide relation inclusion explicitly and must not inherit this split.
- Name-based ortholog classification is asymmetric for reverse edges: is_ortholog_edge checks a hard-coded tuple set plus relation-name substrings (src/models/gnn/layers.py:268-280,399-416). The export's rev_ edges (src/kg/graph.py:678-682) of a set entry such as (mouse_gene, has_phenotype, mouse_phenotype) become (mouse_phenotype, rev_has_phenotype, mouse_gene), which is classified as core (verified). The view must be built from the bound KG's type, species and relation metadata, never from name substrings.
- Dead parameters in every formal build. node_type_encoder (shepherd_gnn.py:129-132) is never reached, because every builder gives every x_dict type an input width (scripts/train_model.py:938-943; shepherd_gnn.py:569-588; scripts/build_index.py:150). pos_encoder is built by default (shepherd_gnn.py:61; create_model_from_config never sets it, train_model.py:947-954) and is never fed. ortholog_gate.species_embedding never gets a gradient. All three were confirmed by a CPU probe and are saved in checkpoints. The new builder must not build unfed modules (regression 2; Codex: no dedicated dead parameters when an option is off).
- README §7 (docs/working/scorer-retraining/README.md:446) still says OrthologGate stays in the heterogeneous encoder. The owner and Codex decision (CLAUDE_DECISIONS §8 and appendix) retires it once S1+S2+S3 land. The retirement list must be updated, and it must also add the unwired NodeClassificationHead, ExplanationHead (heads.py:383-537) and FlexHeteroAttention (flex_attention.py:39-260), which §7 omits.
- Retiring use_ortholog_gate reaches outside src/models: src/config/training_fields.py:255-257 (projects_to ShepherdGNNConfig, checked by tests/unit/test_training_fields.py:523-532), src/api/routes/training.py:133, the WebUI checkbox at src/webui/components/training_console.py:2947-2948 (also :289,357,2709), scripts/probe_deployment.py:2107-2109, the Trainer's flat mirror at src/training/trainer.py:1127-1137, and scripts/run_local_tests.py:194. Per Codex K7, old requests carrying the field must be refused, not silently ignored.
- scripts/build_index.py builds the model on its own (:148-176). It reads only flat config fields with defaults (hidden_dim 256, conv_type 'gat', num_layers 4) and ignores model_config, working today only through the Trainer's flat mirror. It falls back to treating the whole checkpoint as a state dict (:110-112), orders node types by sorted() (:198), has no M2.4 training-record check (serving has one, src/inference/pipeline.py:1214-1226) and no task filter. Its --checkpoint path has no test.
- The run layout is keyed by conv_type: runs/<conv_type>/<run>. list_runs iterates only SUPPORTED_CONV_TYPES (src/utils/checkpoint_paths.py:308-321), normalize_conv_type explicitly rejects 'gatv2' (:81-96), and the WebUI run-id parser checks the same tuple (src/webui/components/training_console.py:1035-1038). Adding the reference encoder touches run listing and selection. The §5 configuration identity should not be conflated with this directory key.
- Layering (.import-linter.ini): src.models and src.retrieval are siblings that must not import each other, and src.models sits below src.training and src.inference. The one builder cannot import src.training (checkpoint_payload, loss_functions) or src.retrieval, so index construction stays in scripts/build_index.py calling the builder. Shared score math (tanh-DistMult, normalised squared distance) must live in src.models so that src.inference.scoring never imports src.training (the scorer-independence contract).
- The spec must be readable without torch: src/models/gnn/__init__.py:146-152 eagerly imports torch and PyG (noted at src/config/model_types.py:4-7). The API, WebUI, inventory and task filter need to read and validate model_spec without torch, so the spec schema belongs in a torch-free module.
- Fixtures write specless checkpoints (tests/fixtures/synthetic_workspace.py:194-205, tests/fixtures/registered_cohort.py:196-208: flat config, no model_config) that rebuild only through resolve_arch_params' key inference. Once the builder refuses specless checkpoints, all 38 dependent test modules fail together, so migrate the fixtures first. About 9 tests also monkeypatch shepherd_gnn.build_shepherd_model by attribute name and break when it is renamed.
- The builder's name is scoring semantics: MODEL_CONSTRUCTION = 'production (build_shepherd_model)' (scripts/measure_scorer.py:211-213) is one of SCORING_SEMANTICS_FIELDS (src/evaluation/sidecar.py:115,143). Changing the builder changes the scoring-semantics digest. New reports should group apart from historical ones, but the change must be deliberate, and historical records keep the old string.
- resolve_arch_params rewrites the recorded config: it forces dropout to 0.0 (src/config/model_types.py:203-205) and fills use_positional_encoding and use_ortholog_gate from which keys are present (:166-169). The new spec must record trained values unchanged and rely on eval(), never mutating the spec at load time.
- Norm semantics differ by encoder: HeteroGNNLayer and ShepherdGNN use per-node nn.LayerNorm (layers.py:175-179; shepherd_gnn.py:171-174), while the reference needs graph-mode LayerNorm plus BatchNorm1d, whose output depends on the node set of the forward pass (§2.6). Serving and measurement do a one-shot full-graph forward (pipeline.py:1364; measurement.py:616). The GraphEncoder contract must declare each encoder's evaluation strategy, and the reference's chunked layer-wise inference is new code. Nothing in src.models today implements GATv2Conv, a learned node table, the DistMult+tanh LP head, the patient encoder or any task head (layers.py:36 imports only HGTConv, GATConv and SAGEConv).
- The Trainer groups weight decay by name substring (src/training/trainer.py:311-312: bias, LayerNorm.weight, layer_norm.weight). That list already misses today's module names (layer_norms.<type>.weight, final_norms.<type>.weight), so norm weights get decay. The new bundle's module names (node table, BatchNorm, graph LayerNorm, relation vectors) will decide the grouping. The reference recipe's wd 0 hides this, but non-reference configurations would not.
- AdaptiveAttentionBackend is not a drop-in for the patient encoder's masked attention: the flash_attn path drops attn_mask (src/models/attention/adaptive_backend.py:113-115), the layouts differ ((B,L,H,D) for flash_attn/xformers against (B,H,L,D) for SDPA, :115-128), it prints on construction (:103), and it imports an arbitrary module named by the ATTENTION_PLUGIN env var (:48-59). FlexHeteroAttention creates nn.Parameters inside forward (flex_attention.py:86-93,139-141), outside the optimizer and with state_dict keys that vary, so a strict load breaks.
- Module headers claim torch.compile compatibility (shepherd_gnn.py:19; layers.py:16; heads.py:18; src/models/__init__.py:36-54), but no test compiles ShepherdGNN; test_models.py:715-741 compiles only NodeTypeEncoder and DiagnosisHead, and skips without a compiler. Codex: claim no compile or accelerator support for an unverified configuration. HGT disables autocast and casts to fp32 (layers.py:203-218). Per Codex 7.4, AMP stays an optional non-reference setting, without banning HGT+AMP again.

**Data, graph and sampling**

- Leak: SubgraphSampler returns the induced subgraph, so every edge among sampled nodes is kept, including the edges a step supervises (src/kg/data_loader.py:424-429). There is no edge-level filter. F5 needs the target edges, their reverses and duplicates removed from each step's message passing, so the induced-subgraph builder cannot be reused as-is.
- Hop semantics: _neighbor_sampling re-expands every node sampled so far on every hop, not only the newest frontier (src/kg/data_loader.py:209-212), and quietly stops at max_subgraph_nodes (:227-230). DIAGNOSIS_SUBGRAPH_HOPS=2 uses only two of the three num_neighbors entries (:779; scripts/train_model.py:913-915). None of this is layer-wise [15,10,5] sampling. Validation ranks only the diseases in each batch's subgraph, not all diseases (U6).
- Unseeded randomness: neighbour draws use global random.sample/choice (src/kg/data_loader.py:220,263). Disease negatives use random.randint inside DataLoader workers (:667). NegativeSampler uses np.random/random (:534-597). F2/F3/U14 need recorded seeds and resumable streams.
- NegativeSampler is dead but looks alive. It is built at src/kg/data_loader.py:820 and never called, and its fallback pads with random ids that are never checked (:548, :597) and can equal a positive. Do not revive it for F1.
- node_features.pt: the export writes random N(0,1) features per type (src/kg/graph.py:634-645), and manifest schema 3 binds them with a recipe (src/kg/artifacts.py:374-433). verify_graph_reads requires node_features.pt to be read (src/kg/artifacts.py:264-275; GRAPH_TENSOR_ROLES :46). The reference recipe uses a learned nn.Embedding table (U2), so every run loads a possibly large tensor it never uses. Dropping it needs a manifest schema change and a plan for historical workspaces.
- Reverse edges are linked only by the 'rev_' name prefix (src/kg/graph.py:677-682). The decisions say to build the view from bound type/species/relation metadata, not from name substrings, and to remove forward and reverse together. The edge split must keep an edge and its reverse in the same part (A3). kg.metadata() omits rev_* (src/kg/graph.py:713-750) while models are built from the graph_data keys (src/models/gnn/shepherd_gnn.py:519-524 warns about this).
- No dedup, native self-loop removal or LCC anywhere: add_edge appends unconditionally (src/kg/graph.py:309-317), and the HPO parser deduplicates only within one file (src/data_sources/hpo_annotations.py:196-200,266-291). MONDO/HPO terms with no annotations still enter the export, linked only by is_a or isolated. The view (G1) must exclude them and keep their ids and reasons in coverage denominators.
- Node indices are per type, in insertion order, and node types are ordered by the first insertion of each type (src/kg/graph.py:248-251,752-766; export iterates node_mapping at :638-645). A homogeneous global node table needs a deterministic type order plus offsets, shared by sampler, SP, scorer, serving and the PathReasoner mapping. Order sensitivity is already tested for HGT (tests/unit/test_hgt_node_type_order.py).
- kg.json drops edge metadata: save_json keeps only endpoints, edge_type, weight and confidence (src/kg/graph.py:832-845) and no node data_sources. The ortholog_type set by add_orthologs (src/kg/builder.py:534) and edge data_source/evidence are lost, against decision §五.6 to keep source, species, orthology type and confidence.
- Cross-species data is not wired: build_knowledge_graph never calls add_orthologs and sets include_orthologs=False (scripts/build_knowledge_graph.py:268-272). OrthologDataSource is a skeleton that returns [] (src/data_sources/ortholog.py:139-156,205-217,337-349) yet protocols.py:474 labels it IMPLEMENTED. add_ontology would give MP terms DataSource.HPO (src/kg/builder.py:180-183,226-232). The demo mouse gene has no species (scripts/setup_demo.py:233-238). Provenance SOURCE_ROLES is fixed at four roles (src/kg/provenance.py:60). Regression 11 must therefore use synthetic graphs built through the real builder and kg.json path.
- SP today is neither the gene SPLSIM nor view-bound. It is computed on the raw kg.json, relation-blind and undirected, over every edge including ortholog and duplicate edges (scripts/compute_shortest_paths.py:94-108). It is capped at max_hops=5 and drops beyond-cap pairs (:84, :152-166), so unreachable and beyond-cap cannot be told apart. sp_mean_distances substitutes max_hops+1 (src/inference/sp_index.py:150-157,545), which §6 forbids. The binding is to kg_digest only (src/inference/sp_artifact.py:319-357), not to a view or node mapping. The size of an exact, uncapped phenotype×gene table has not been measured (int8 distances, 9 bytes a row).
- Sample row semantics: gene_ids are all of the disease's associated genes (src/kg/sample_generator.py:729), not a candidate list and not a causal gene. Every sample has exactly one disease_id (:726; src/kg/storage/file_storage.py:298-318). F9 multi-positive truths and the gene and patients-like-me tasks need new optional fields and a reader extension. The training reader currently projects only two optional fields.
- Fixture leakage risk: disease profiles include phenotypes propagated from gene_has_phenotype through the disease's genes (src/kg/sample_generator.py:641-648). A gene-task fixture whose causal gene is drawn from the disease's genes will therefore often sit 1 hop from the generated phenotypes on the very edges SP and message passing traverse. Acceptable for a functional fixture, but it must not be read as task difficulty.

The view, the edge split (F2) and the task fixtures for existing workspaces therefore need a separate derived-artifact writer that never rewrites the six manifest-bound files.

KnowledgeGraph.metadata() and to_pyg_hetero_data() then have no code caller left (src/kg/preprocessing.py:269-272).

**Inference and evaluation**

- Candidate discovery is the ranking gate today: _score_and_rank_candidates builds entries only from all_paths keys (src/inference/pipeline.py:1840-1847), and discovery is capped (path_reasoning.py:105-106 max_paths_per_source=100, max_total_paths=10000; enforced at :207,:242).
